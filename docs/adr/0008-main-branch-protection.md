# 0008. Защита main

- Статус: Proposed
- Дата: 2026-10-14

## Контекст

- На Free-плане rulesets не работают для приватных репозиториев.
- Перед публикацией — gitleaks по всей истории: no leaks.

## Решение

- Ruleset protect-main без bypass:
  - запрет удаления и force-push;
  - изменения только через PR (merge commit);
  - обязательная проверка "build" (github-actions), strict.
- Репозиторий публичный; secret scanning + push protection включены.

## Проверка

Проверка негативными тестами:
- fast-forward push отклонён (правило метода merge);
- push пустого коммита вне PR отклонён («через PR» + "build").

## Рассмотренные варианты

- **Приватный репозиторий + платный план** — отвергнут: затраты не оправданы для учебного проекта.
- **Защита без ruleset (только договорённость)** — отвергнута: не проверяется механически.

## Последствия

- \+ main нельзя изменить без PR и зелёного build, в том числе админу.
- − 0 approvals — ревью не гарантировано механически (свой PR одобрить нельзя); план: отдельная идентичность агента.

Инцидент: push merge-коммита с головой зелёного PR #2 принят как CLI-merge PR #2 (92ec357). Вывод:
- негативный тест делается коммитом вне любого PR;
- причина отказа сверяется дословно по rule suites API;
- на каждое правило — свой тест.

Запланировано: тест «merge до окончания CI» выполняется на PR этой задачи; результат записывает человек в docs/agent-journal.md.
